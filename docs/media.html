让 agent 做事 / What Agents Can Do

截图·录像·视口

让 agent 把浏览器里看到的东西存成文件：截一张图、录一段操作视频，或者把页面缩到手机宽度检查布局。截图用来留档和给你看；agent 找按钮、点按钮靠的是页面结构，不靠截图。

你可以这样说

把这个页面整页截下来，存到 docs/images/ 里。

截整个滚动高度，不只是可视区。

把下单流程录成视频，我要发给同事看。

关键步骤之间留停顿，1 倍速也看得清。

用 375 宽的手机尺寸看看这个页面，哪里横向溢出了？

只改这个标签页的布局宽度。

agent 会怎么做

  1. screenshot 截当前视口，--full 截整页，也可以只截某个元素或某块区域。
  2. 需要对着图讨论时加 --annotate，图上的编号对应 agent 读到的页面元素。
  3. 录像用 record start 和 record stop 包住整段操作，关键动作之后留一点等待。要发到 issue 或聊天里的，录成 .gif。
  4. 查响应式问题时用 viewport 设好宽高，再比较页面宽度和视口宽度，找出撑破布局的元素。
  5. 普通提示框会自动关掉；页面弹出确认框或输入框挡住流程时，用 dialog 接受或取消。

你会看到什么

  • 你的标签不受影响：agent 在你 Chrome 里的 ✦ 项目名 标签组中开后台标签，不抢焦点，你想看随时点过去。
  • 截图不指定路径时存到临时文件，路径会打印出来；你想放哪里直接告诉 agent。截图默认缩到最长边不超过 1200px（整页截图只限宽度），要原尺寸可以说。
  • 录视频（.webm 或 .mp4）要本机装有 ffmpeg；录成 .gif 不需要，GIF 每秒 5 帧、宽不超过 800px，可以直接贴进 issue。通过扩展连你的 Chrome 时，录的是 agent 自己的标签页。
  • 改视口只影响这个标签页的布局，你的 Chrome 窗口大小不变。
  • 任务结束时 agent 用 done 收尾：中间打开的标签关掉，你要看或要接着用的页面留下。

底层命令

下面是 agent 实际调用的命令和参数。自己写脚本、排查问题或想了解细节时看这部分。

这一页讲的是「把浏览器里发生的事变成文件」：抓一张 截图、录一段 工作流视频、把视口缩到手机宽度复现响应式 bug， 以及处理挡在中间的 iframe 与弹窗。它们都是输出手段—— 不是用来「找元素、点元素」的。定位和交互请始终走 snapshot + @ref。

⚠️ 硬性规则：截图用于留档，不用于定位
永远不要靠「截图 + 坐标点击」去找或命中一个元素——那是 bug。表单字段、按钮、 链接都用 snapshot -i 拿到 @ref，它连 跨源 iframe（内嵌的 Stripe / Google Payments / 结账框）都能穿透。 截图只负责把渲染结果存成可复用的图片资产（地图、图表、og 图、视觉回归基线、报告插图）。

截图

screenshot --annotate 在 CLI 中把编号绘制到截图上，不会向页面插入节点或样式。JSON 标注框仍使用相对截图区域的 CSS 像素，图中的编号按图片分辨率缩放。显式裁剪区域优先于全页和元素截图。 框架引用使用所属渲染进程和顶层视口坐标。嵌套跨进程 iframe 通过协议四边形和隔离世界中的视口尺寸测量支持旋转、倾斜、镜像和透视变换，视口尺寸包含滚动条占用的空间，标注框包围投影后的四个角点。变换退化、数值不稳定、跨越透视无穷远线或框架几何信息缺失时会明确报错，不会猜测标注位置。 裁剪也在 CLI 中完成，视口外区域从全页截图中裁出。超出页面范围的区域会被拒绝。

扩展中继为每次截图捕获保留最多 25 秒，低于 CLI 的 30 秒 CDP 期限。视口或 DPR 改变后，Chrome 原生截图可能比普通命令更慢。这里等待的是同一次捕获，不会重放命令或激活标签。超时仍会报错，也不会取消 Chrome 中尚未完成的捕获，因此应避免重叠重试截图。

screenshot 把当前页面渲染成 PNG。不带路径时存到临时文件并把路径打到 stdout；带路径就写到指定位置。

screenshot.sh 
$ chrome-use screenshot                        # 临时路径，打印到 stdout
$ chrome-use screenshot page.png               # 指定路径
$ chrome-use screenshot --full full.png        # 整个滚动高度
$ chrome-use screenshot --annotate map.png     # 编号标注 + 图例，对应 snapshot 的 ref

--full 抓的是整页滚动高度而非只有可视区。 --annotate 是给多模态模型看的：每个标签 [N] 对应快照里的 @eN，方便把一张图和结构化快照对上号。它只刷新当前文档的标注，不会硬重置 ref 映射；紧接在截图前一次快照里的 ref 仍可继续操作。

缩放与裁剪

真实 retina Chrome 的整页截图往往太大、塞不进图片阅读器，所以截图会 自动降采样到最长边 ≤1200px（整页截图只限制宽度，加 --full-res 保留原尺寸）——这样既能被阅读器读取，像素坐标又能和 click x y 对齐。需要时用下面的开关覆盖，或只截某个选择器 / 某块区域：

bash 
# 只截某个元素 / 某块区域，存成可复用图片资产
$ chrome-use screenshot "selector" --clip x,y,w,h region.png

# 覆盖默认降采样上限
$ chrome-use screenshot --max-width 1600 wide.png
$ chrome-use screenshot --scale 1 sharp.png
ℹ️ 关于滚动条
无头 Chromium 截图会隐藏原生滚动条，保证输出图一致。启动时传 --hide-scrollbars false 可以保留可见的原生滚动条。
✅ 想点一个 ref 点不到的东西？
不要靠截图找坐标。用 box @ref 拿到元素的 CSS 像素框和 centerX/centerY，直接喂给 click <centerX> <centerY>——全程不需要截图。

录制工作流视频

把一整段自动化录成视频，用于调试、写文档或留证据。 record start 开始录，中间正常跑你的命令， record stop 结束并落盘。 通过扩展连接真实 Chrome 时会直接录当前 session 拥有的标签页，不会调用 Chrome 禁止的 Target.createBrowserContext；--launch 模式仍使用隔离 context。

record.sh 
$ chrome-use record start demo.webm
$ chrome-use open https://example.com
$ chrome-use snapshot -i
$ chrome-use click @e3
$ chrome-use record stop

还有一个 restart 子命令，等价于「停掉当前录制 + 用新文件开录」：

bash 
$ chrome-use record start ./output.webm       # 开始录制到文件
$ chrome-use record stop                     # 停止当前录制
$ chrome-use record restart ./take2.webm    # 停当前 + 用新文件重开

录成 GIF

路径以 .gif 结尾就录成循环播放的动图，适合贴进 issue、PR 或聊天。 record start --gif 不写路径时存为 ./recording.gif； --gif 配一个不是 .gif 的路径会直接报错。

bash 
$ chrome-use record start ./bug.gif
$ chrome-use click @e3
$ chrome-use record stop                     # 打印路径和帧数

GIF 在 chrome-use 里边录边编码，不用 ffmpeg，录多久内存都不涨。每秒 5 帧，宽度缩到不超过 800px， 整段沿用第一帧的尺寸；画面没变的帧合并成一帧，页面静止时几乎不占空间。 每帧最多 256 色，界面看得清，照片和视频会有颗粒感，画质要紧时录 .webm。

录制的实用做法

目标做法
让人看清每一步 在关键动作后插 chrome-use wait 500，给观看者反应时间
文件名带上下文 login-flow-2024-01-15.webm、checkout-test-run-42.webm
出错也要保住录像 用 trap cleanup EXIT 里调 chrome-use record stop
视频 + 关键帧一起留 录制的同时在每一步 chrome-use screenshot ./stepN.png 抓帧
ℹ️ 输出格式与限制
录视频通过 ffmpeg 把 CDP 截帧编码，所以机器上得装好 ffmpeg。输出格式由文件扩展名决定： .gif 由 chrome-use 自己编码（不需要 ffmpeg），.webm 走 VP8（libvpx），其它扩展名（比如 .mp4）走 H.264（libx264）。 录制会给自动化带来轻微开销，长录像很占磁盘，个别无头环境可能缺编解码器。 skill 包里的 references/video-recording.md 有更多录制范例（仓库内文件，文档站不提供跳转）。

Iframe 作用域

iframe 的内容会自动内联进快照，refs 直接透明可用——通常你什么都不用做：

bash 
$ chrome-use snapshot -i
# @e3 [Iframe] "payment-frame"
#   @e4 [input] "Card number"
#   @e5 [button] "Pay"

$ chrome-use fill @e4 "4111111111111111"
$ chrome-use click @e5

当你想把快照聚焦到某个 iframe（为了专注，或处理深层嵌套）时，用 frame 切换上下文，处理完再 frame main 切回主框架：

bash 
$ chrome-use frame @e3      # 把上下文切进这个 iframe
$ chrome-use snapshot -i
$ chrome-use frame main     # 切回主框架

视口 / 窗口尺寸

要复现依赖宽度的 bug（响应式断点、横向溢出排查、移动端布局），先设视口。 这是一个 CDP 虚拟视口（Emulation.setDeviceMetricsOverride）—— 它只改这个标签页的布局视口，不会真的去缩放操作系统窗口。所以无头能用， 走扩展中继（extension relay）时也能用，而不会去拉扯用户真实的 Chrome 窗口。

viewport.sh 
$ chrome-use viewport 1280 800        # 设宽 x 高（别名：resize）
$ chrome-use viewport 375x812         # WxH 简写
$ chrome-use viewport 375 812 --dpr 3 --mobile   # retina + 移动端模拟
$ chrome-use viewport reset           # 清除覆盖，恢复真实尺寸

典型用途——找出在窄宽度下是什么撑破了布局：

bash 
$ chrome-use viewport 375 812
$ chrome-use eval 'document.documentElement.scrollWidth + " vs " + innerWidth'
✅ 等价别名
set viewport <w> <h> [scale] 与 viewport 等价，resize 也是别名—— 怎么顺手怎么写。

set device "iPhone 13" 使用 390 × 844 CSS 视口、3× 缩放和 iOS 15 用户代理。 set device off（别名 reset、none，也可写 device off）清除当前标签页的设备尺寸、 用户代理和触摸模拟覆盖，新标签页也不再继承模拟的用户代理。 复位后会读取真实视口尺寸，不调整 Chrome 窗口大小；中途失败会说明已清除了哪些覆盖。 viewport reset 只清尺寸覆盖，保留用户代理设置。

弹窗对话框

alert 和 beforeunload 会被自动接受， 这样 agent 永远不会被弹窗卡住。需要手动处理 confirm 和 prompt 时：

dialog.sh 
$ chrome-use dialog status          # 有没有待处理的弹窗？
$ chrome-use dialog accept           # 接受
$ chrome-use dialog accept "text"    # 接受并填入 prompt 内容
$ chrome-use dialog dismiss          # 取消
ℹ️ 什么时候需要它
大多数流程不用碰 dialog——原生 alert 已自动放行。只有当页面弹出 confirm（「确定要删除吗？」）或 prompt（要求输入一段文本）并阻塞后续操作时， 才用 dialog accept / dialog dismiss 明确应答。
