插件对话 / Chrome 扩展

插件对话

在 Chrome 侧栏里写下任务，让本机 agent 使用已登录的浏览器完成操作。扩展沿用你安装的 CLI 和它配置的模型服务。

先安装 chrome-use，运行 chrome-use extension install 注册原生宿主，再安装 Chrome 扩展。本机至少安装并登录一个受支持的 agent CLI，然后打开侧栏。

开始对话

点击扩展图标打开侧栏，Settings 打开连接设置。macOS、Linux 和 Windows 可选择 Codex、Claude Code、OpenCode 或 Pi，沿用已安装 CLI 的登录。主机会报告支持哪些 agent，旧主机可能需要升级。Windows 同样支持技能、图片、会话参数、定时任务及配置应用和恢复。停止、删除或更改参数会确认整个 agent 进程树退出；私有数据通过 Windows ACL 限制为当前用户和 SYSTEM 访问，不需要管理员权限。Codex 走 app-server，Claude Code 走 stream-json，OpenCode 走 ACP，Pi 走 JSONL RPC。

页面与模型

每个会话使用独立浏览器 session。输入框上方的页面标签会随下一条消息附带当前网页，点 × 可去掉。模型下拉来自所选 CLI 的目录，Default model 沿用配置的模型，＋ 菜单中的 Custom model ID 可覆盖选择，Reload models from CLI 重新读取目录。列出模型或报告已登录不代表实际调用可用。

每个标签页一个侧栏

点工具栏按钮会为当前标签页打开侧栏。每个标签页有自己的侧栏和对话：切到别的标签页时，侧栏显示那个标签页的对话，没在那里打开过就不显示；切回来原来的对话还在。在新标签页上打开侧栏会开始新对话。选择另一个标签页正在显示的对话，会把它移到当前标签页。关闭标签页后，它的对话仍保留在历史里。

agent 在哪里工作

标签页侧栏里的对话默认就在这个标签页里工作：第一条消息会把标签页借给这个对话，agent 用你的登录状态读取并操作你的页面，而不是另开自己的窗口。输入框上方的 agent 工作位置 可以把单个对话切换为 这个标签页 或 它自己的窗口；默认值在 设置 → 侧栏 agent。借出的标签页：

  • 只由这个对话操作：没有指定标签页的命令都在这里执行，每条消息也会告诉 agent 它可以用哪个标签页。它不会关闭或移动这个标签页，其他对话也不能使用它。
  • 工具栏图标显示 AI 徽标（悬停可看到对应的对话），侧栏顶部有一条提示写明标签页和所在网站。agent 连接时 Chrome 还会显示调试提示条。页面本身不会被加入任何东西。
  • 点 收回标签页、删除对话或关闭标签页即可收回。调试器会脱离这个标签页，这个对话之后的命令会被拒绝，并提示你已收回。收回后对话会切换为 它自己的窗口；再选 这个标签页 即可重新借出。停止 只停止当前回复。你在终端里运行的 chrome-use 命令不受影响。
  • 跳转到别的网站后仍保持借出，提示条显示新的网站。Chrome 自身页面和 Chrome 应用商店不能借出：在这类页面上 agent 会在它自己的窗口里工作，侧栏会说明。

侧栏顶部的箭头按钮 在标签页中打开 会把当前对话作为整页标签页打开，内容居中加宽。侧栏和整页标签页可以同时显示同一个对话：两边都实时更新，消息只会从你输入的那一边发出。整页标签页旁边没有页面，所以它的页面标签指你在该窗口最后使用的网页标签页（可在列表里另选），也不会自动借出：点 让 agent 使用这个标签页 才会借出标签里的页面。

借出在 Chrome 重启后失效。每个标签页一个侧栏和在侧栏所属标签页里工作需要 CLI 1.5.223 和扩展 0.5.63 或更高版本。

工具权限与审批

权限开关只作用于当前会话。新会话默认开启 Full access，除非你保存过其他选择。

  • Codex / Claude Code：关闭后显示 Ask first，由你处理审批请求。完整权限模式不再逐次询问，并自动回复支持的审批；agent 提问仍需你回答。
  • OpenCode：CLI permissions 遵循它自己的规则，部分工具可能无需询问。收到的审批会显示在侧栏，完整权限模式按 Allow once 自动回复，不改保存的权限规则。
  • Pi：没有逐次审批机制。Browser only 只开放 chrome_use MCP 工具，不开放 shell 或文件工具；完整权限模式使用 CLI 的完整工具集。

排队、停止与继续

历史显示流式回复，工具行可展开查看。工具返回不代表浏览器任务成功。回复中发送的消息进入队列，失败或中断后需点 Resume queue 恢复。 失败或中断后，新发的消息会在原会话中使用原模型立即开始；旧队列仍暂停，需手动恢复。Stop & send 或 Ctrl/Cmd+Enter 等确认终止或进程退出后才优先发送，普通队列仍暂停。重连只读回历史，不重发。

历史与删除

删除前先停止回复，再点顶部删除按钮并确认。删除内容包括面板历史和该会话的浏览器 session，以及 Codex rollout 文件、Claude 会话文件及目录、通过 session/delete 删除的 OpenCode 历史，或会话文件夹内的 Pi 会话文件。Codex 的 SQLite 缓存不改动。清理失败或标签页关闭未确认时会提示。

会话菜单每行右侧的窗口按钮会定位该会话最近记录的 agent 网页；页面已关闭时，按最后记录的 HTTP(S) 网址重新打开。左侧标题只切换聊天。此操作不会发送消息或重跑任务，也不会恢复未保存的输入；没有记录网页时会提示。网页地址仅保存在本机扩展存储中。删除会话会等待地址清理完成，存储失败时明确提示。

继续终端里的会话（/resume）

在输入框里输入 /resume（可以加搜索词），或在会话菜单里选继续已有会话…，就能接着用在终端里开始的 CLI 会话。选择器列出这台电脑上该 agent 最近的会话，按项目文件夹分组：最近有活动的项目排在前面，当前网站记住的项目排在最前，没有文件夹的会话放在“其他”里。每个项目先显示最近的 3 个会话，点展开显示看其余的；点项目名可以折叠，鼠标悬停显示完整路径。搜索会匹配标题、项目名和路径，结果仍按项目分组。用 ↑↓ 选择、回车继续、Esc 关闭。最近活动时间取自会话记录里的时间，不看文件的修改时间（Codex 桌面版导入其他 agent 的会话时会重写文件）；只有会话刚写过记录或有未结束的轮次时才标记“在别处运行中”。Codex 的子 agent 线程不会列出。面板自己开的会话不会列出，已经在面板里继续过的会话会直接打开对应的会话。选中后会新建一个绑定到该会话的对话，在你发出下一条消息之前什么都不会发送，agent 回复时会带着之前的上下文。

  • Claude Code / Codex：agent 在该会话自己的文件夹中运行，并接着写它原来的会话文件。
  • OpenCode：按会话自己的文件夹恢复；面板通过 OpenCode 自己列出会话。
  • Pi：面板会接着用原来的会话文件，但 Pi 运行在会话的私有文件夹里（它从运行目录读取 MCP 配置），所以它的文件工具看不到项目。

最近一分钟内写入过、或仍被运行中的 Claude Code 进程占用的会话，会标为在别处运行中。继续这类会话前需要先确认，因为两个程序同时写一个会话可能损坏它的历史；在这里继续之后，请不要再同时在终端里使用它。会话此前的消息显示在折叠的此前的会话内容里，导入时和其他历史记录一样先脱敏，最多保留最近 40 条；更早或无法读取的部分会注明更早的历史没有记录。会话的文件夹会作为项目，前提是它和手动选择的文件夹一样通过检查；如果它是系统文件夹或主目录，Claude Code 和 Codex 会改在私有文件夹中继续并在面板里提示，OpenCode 只能在会话自己的文件夹中继续，因此会拒绝。CLI 自己的会话文件只读不写，删除这样的会话时也会保留 CLI 会话。需要 CLI 1.5.220。

项目文件夹与网站 ↔ 项目

默认情况下，会话里的 agent 在它自己的私有文件夹中工作。如果要在某个项目里工作，请在发出第一条消息前，点 agent 旁边的文件夹标签（没选时显示不选工作目录）选择文件夹：最近用过的文件夹来自以前的面板会话、最近的 Claude Code 和 Codex 会话，以及点选改代码里绑定过的网站；选择文件夹…会打开系统的文件夹选择器（Linux 上没有选择器时可直接输入路径）。文件夹必须存在，不能是主目录本身、存放多个项目的上层文件夹（如 /Users、/opt），也不能是系统文件夹或其中的任何文件夹（如 /etc、/usr、/System、/opt/homebrew；Windows 上为 Windows 和 Program Files）。它在创建会话时确定，之后不可更改，并显示在会话顶部。Pi 会话始终使用私有文件夹。

只有 agent 在项目里工作。面板自己的文件（MCP 配置、附加的图片，以及浏览器操作产生的截图、下载和录屏）都保留在会话的私有文件夹里，不会写进项目。

代码托管网站上的仓库页面会自动对应到本机的仓库副本。打开 github.com/<用户>/<仓库> 下的任何页面（PR、issue、文件），以及 GitLab（含子组）、Gitee、Bitbucket、Codeberg 和自建的 Gitea、Gogs、GitLab 上同样的页面，面板会在最近用过的文件夹里找 git remote（origin、upstream 或其他远程，https、ssh 和 git@host:owner/repo 写法都可以）指向这个仓库的那个，新会话默认用它，文件夹下方显示按仓库匹配：<仓库>，不需要点任何东西。自建服务器靠本机仓库的 remote 认出来，不需要事先配置；remote 只从 .git/config 读取（git worktree 也能识别），不会运行 git。ssh 远程用的是 ~/.ssh/config 里的主机别名（如 git@github-work:owner/repo）时，按该别名的 HostName 对应（只读取，不跟随 Include）。

同一个网站下有很多项目的，也按项目对应，不按域名：App Store Connect 的应用（/apps/<appId>，含 TestFlight 页面）、Vercel 项目（/<团队>/<项目>）、Netlify 站点、Cloudflare Workers 和 Pages、Firebase 和 Google Cloud 项目（路径里的项目 ID 或 ?project=）、Sentry 项目。如果最近用过的文件夹根目录里有文件写明了这个项目，就自动选中它：fastlane/Fastfile、Appfile 或 Deliverfile 里的 App Store Connect 应用 ID，.vercel/project.json 或 vercel.json 的项目名，wrangler.toml/wrangler.json 的 name，.firebaserc 的项目 ID，.sentryclirc 或 sentry.properties 的 project。面板显示按项目匹配：…。Netlify 没有可对应的本地文件，靠下面的“记住”。这些规则在 CLI 里是一张表，新增网站只需加一行。

网站也可以记住它的项目，和点选改代码共用同一份绑定。在另一个文件夹里新建会话后，面板会问以后在 <范围> 上都用这个项目吗？，范围可以在提示里直接改：仓库页面默认是这个仓库（如 github.com/leeguooooo/image-use），App Store Connect 默认是这个应用，Vercel 等默认是这个项目，并用页面标题里的名字称呼它（如“Hellow（appstoreconnect.apple.com/apps/1234567890）”）；也可以选这个路径或整个网站。其他网站默认是整个网站，也可以只选当前路径。有很多项目的网站不会默认绑定整个网站；项目只写在 ?project= 里的（Google Cloud、部分 Sentry 页面）无法按项目记住，只能按路径记住，但仍会自动匹配。点记住即可保存，如果这段时间里该范围的绑定已经改变，则不会覆盖。

选择顺序：覆盖当前页面且范围最长的绑定优先；绑定在这个仓库（或仓库里的某个路径）上的项目，胜过自动匹配到的仓库副本；范围更宽的绑定（整个网站、某个用户）不会盖过仓库副本，只在有多个副本时决定用哪个。已有的整站绑定不会被删除。可以在扩展选项页的已绑定到项目的网站里查看、修改范围或删除这些绑定。用 /resume 继续的会话以该会话的文件夹作为项目。

隐私与配置

工具和审批记录中的已识别敏感字段与凭据格式会在写入本机记录前遮盖，已知敏感值也会从后续显示文本中移除。这不覆盖你自己的消息原文、图片像素、文件内容或 CLI 自己的历史；后来才识别的敏感值不能抹掉此前文本。结果文件随会话保存，删除会话时一并清理。详见隐私说明。

历史保存在本机。所选 CLI 可能把任务和网页内容发送给它配置的模型服务，该服务的隐私政策适用。侧栏没有新增网页 content script，打开时仍可能改变页面视口。Agents & models 可发现程序和预览配置改动，写入后读回，恢复时保留后来的修改。

技能和图片

输入 / 选择技能，可以在消息开头，也可以在消息中任意空格之后；用 ↑↓ 移动，Tab 或回车选中，Esc 关闭。列表包括已启用的 Claude Code 插件里的技能。在 Agents & models → Skill library 编辑、启停库内条目，或从本机目录、ZIP/.skill 压缩包、HTTPS Git 仓库导入。用户和 CLI 原有技能目录在这里只读。发送前保存所选技能及文件的副本，队列编辑和明确重试保留同一份内容。面板 agent 可通过 chrome_use_skills 列出、读取技能或保存库内说明。

通过 Attach images 选择图片，也可粘贴或拖入，每条消息最多五张 PNG/JPEG/WebP/HEIC。HEIC 由本地 CLI 用系统编解码器转成 JPEG：macOS 用 sips，Windows 需要从 Microsoft Store 安装 HEIF 图像扩展和 HEVC 视频扩展，Linux 需要 heif-convert 或带 HEIF 支持的 ImageMagick。转换后的照片会按方向转正，并去掉包括 GPS 在内的 EXIF 信息。最长边缩到 2000 像素，每张不超过 512 KiB。图片随会话保存，队列编辑和重试会保留，删除会话时一起清理。ACP agent 必须声明支持图片输入。附件会交给配置的模型服务。

会话参数和定时提示

Conversation options 设置允许的工具、Codex/Claude 推理强度和 Codex 服务等级。空闲时保存，下一次回复生效，不改 CLI 全局配置。Codex 无法移除可以读文件的 shell，OpenCode ACP 无法保证限制内置工具。审批开关只决定是否自动处理当前工具范围内的请求，Pi 没有逐次审批。

Agents & models → Scheduled prompts 支持间隔、每天或工作日的本地时间、五字段 cron，并保存 agent、模型、会话参数、技能和明确的工具范围。每次运行使用独立后台浏览器 session，保留历史并在完成时通知。Run now 不改变下次到期时间。关闭侧栏不会停掉本地服务，停止服务则不再调度。重启或唤醒后，错过的周期只补跑一次；上次仍在执行或结果未确认时不会重叠执行或重放，确认未知结果前先看历史。

侧栏任务完成、失败、被停止、需要恢复或等待批准时，Chrome 会弹出通知，工具栏图标显示未看的数量；点通知会在侧栏打开对应会话。侧栏已在当前窗口显示的会话不会通知。可在 Settings → Notify when a task finishes 关闭。

聊天不能创建比自己工具范围更大或审批权限更高的任务。定时聊天可以列出任务，但不能修改或触发任务，也不能重写供未来任务使用的技能库。agent 已结束不代表网页目标已达成。

每条请求的过程与结果

需要 CLI 1.5.215 和扩展 0.5.58。旧扩展保留原来的显示方式；Chrome Web Store 的提交、审核和公开发布与 CLI 发版分开进行。

每条消息显示为一张卡片，包含随消息附加的页面、浏览器步骤、回复、结果文件和本轮结束状态。运行中的步骤展开，结束后可折叠；失败步骤仍会显示在摘要里。旧历史没有记录的信息会标为 not recorded，不会补猜。

附加页面与实际操作页面

Sent with 是你发送消息时附加的页面；Acted on 是浏览器操作回执确认过的页面。AI 可以打开新标签页，所以两者可能不同。只有缓存目标、缺少操作回执时，显示 Browser tools pointed at。你自己切换标签页不会因此被记为 AI 操作过的页面。

检查通过表示什么

标签含义
Agent's browser checks passedagent 为这条请求选择的浏览器检查已通过。展开查看具体检查；这不保证它完整理解或满足了你的要求。
Some checks passed部分检查通过，其余未检查、未通过或缺少有效证据。
Not checked / Blocked没有可支持结论的检查，或任务被登录、人工验证、缺少输入等条件阻塞。

输入值读回、页面断言、落地地址和下载类型分别只证明对应的检查。文件存在不等于内容正确，截图也不自动证明任务完成。本轮结束、浏览器检查通过和用户目标达成都应分别判断。

截图、下载与录像

结果文件显示为卡片，列出类型、大小和可用状态。文件读取会校验内容；文件丢失或改变时会显示不可用。文件存在、类型匹配，以及是否满足要求分开呈现。保存到 agent 指定位置的结果，也与会话中保留的副本分开报告。

发送前勾选 Record this task 才允许录制这一条请求。录像会经历录制、处理、可读取等状态，回答结束不代表录像已完成；缺少编码器或处理失败会明确提示。未勾选时不会为了显示进度自动录屏。

任务状态未知时怎么办

Stop requested, waiting for confirmation 表示已请求停止，尚未确认。This conversation's agent has stopped 仅说明这个会话的 agent 已停止，不代表其他会话也已停止。

  1. 出现未知结果时，先点 Review what may have happened 查看可能已执行的动作、最后页面和结果文件。不要直接重做发送、付款或提交。
  2. 只有能确认归属的旧进程仍在运行时，才会提供 End the old agent process。
  3. 确认旧进程已退出后，可点 Continue in a new conversation，带着原历史的关联信息继续。创建新会话不会自动重发旧请求。

进程状态仍未知时不会开放继续按钮。服务重启后，某些平台无法再核实旧进程树，界面会保留未知状态。

长任务与历史连续性

重复结果、连续失败或长时间没有活动会显示提示；提示本身不会停止任务或自动重试。可以停止、继续等待，或查看步骤判断原因。上下文压缩会留下标记，历史记录仍保留；压缩不会把未经检查的动作变成成功。
