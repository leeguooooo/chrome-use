## 扩展布局回归

状态回执候选的完整本地测试通过：1261 单元测试、11 CLI 集成测试，3 项忽略。多层按钮包装布局通过商品脚本。普通 div 卡片布局在第一条观察失败，按钮没有 context；长描述布局则明确截断，但价格被描述挤出。这两次结果不能算作任务完成。

源码检查确认 build_tree 会清空 ignored AX 节点的角色，同时保留其父子关系。后续候选允许在这些结构节点中查找单标题上下文，并优先放入短字段；新增测试尚在运行，浏览器还未复测。

修复后复测：generic 和 long 两种布局均通过商品脚本，各 3 条任务命令。两者均依据首次观察选择正确商品，点击后的观察出现正确回执，独立读回一致。long 模式的价格与库存位于截断前，长描述仍有明确截断标记。对应 3 项上下文定向测试通过。输出预算续读与 Codex 对照仍待验证。

## 输出预算续读

`bench/context-budget-check.py` 在长描述商品页以 200 字节树预算逐页续读，通过逐行相等检查确认没有重复或遗漏；续读获得的商品引用仍可正确加购，点击观察含实际回执。共 10 条检查命令，浏览器发现和关闭另计。

预算约束的是 snapshot 树，不是整个 JSON 响应；单个节点超过预算时完整返回该节点。这两项均为现有语义，不能把此次验证写成严格的工具输出字节上限。

## 内置 browser-use 同页任务观察

本 agent 使用当前内置 CUA Chrome extension 浏览器，在 generic 商品页完成同一任务。createBrowserTab 返回的页面 AX 直接显示三个商品的价格、库存、同名加购按钮及 Cart empty；第二次调用执行 click(16) 和 getAXState，返回 Cart: folder。共 2 次 CUA 调用，无动作失败。第二次返回包含整页状态，未据此推断 diff 的内部判定机制。测试标签随工具自动清理。

chrome-use 候选检查脚本有 3 条任务命令，第三条是独立读回验收；完成任务所需的价格、选购和回执已出现在前两条。CLI 命令数与 CUA 调用次数并非同一种成本单位。CLI 使用独立 Chrome for Testing，CUA 使用实际 Chrome，且一侧为脚本、一侧为 agent，因此这不是严格的模型耗时或字节基准。

可确认的结论：候选补齐了原交互观察丢失价格和状态回执的缺口，在这个任务的信息充分性上达到内置工具的表现。尚无证据证明全面超过；更大的页面、真实站点、同环境重复任务与失败恢复仍需比较。
